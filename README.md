# LibLog — Library Logbook Management System> A full-stack Library and Logbook Management System with QR-based check-in, book borrowing, real-time occupancy tracking, and analytics — built for college libraries in the Philippines.\---## OverviewLibLog is a dual-platform system designed to modernize library operations. It combines a **desktop app** for the librarian's station and a **mobile app** for students and faculty — both connected to a shared cloud backend.The desktop app handles everything on the library floor: scanning student QR codes for attendance, processing book borrows and returns via webcam, and monitoring how many students are currently inside. The mobile app gives students access to the book catalog, their personal QR code, and library occupancy status from anywhere — even outside campus.\---## System Pages|Page|Description||-|-||**Dashboard**|Overview of all library operations — occupancy, borrows, overdue books, top visitors, recent activity, and charts||**Literatures**|Full book catalog with author and genre sub-views, book QR management, and add/edit modals||**Borrowing**|QR-based borrow and return flow, active records table, overdue tracking, and penalty management||**Attendance**|Student check-in/check-out via QR scan, weekly heatmap, occupancy panel, and today's full log||**Reports**|Configurable analytics by period — book metrics, user metrics, administrative tracking, and trend charts||**Settings**|User management, library rules configuration, and announcements||**Notifications**|Real-time event feed categorized by Attendance, Borrowing, Penalties, and System|\---## Tech Stack### Desktop App (Librarian Station)|Layer|Technology||-|-||Shell|Electron||UI Framework|React||Styling|Tailwind CSS||QR Scanning|html5-qrcode (webcam-based)||QR Generation|qrcode (npm)||HTTP Client|Axios|The desktop app runs on the library PC. All tables are in PostgreSQL with proper foreign key constraints, indexes, and triggers.### Tables|Table|Purpose||-|-||`users`|All system users — students, faculty, and admins. Stores student ID, card number, QR code, program, role, status, and penalty balance||`programs`|Academic programs like BS Midwifery and BS Public Administration||`authors`|Author records linked to books, used by the Author Catalog view||`genres`|Book genre categories with color codes for the UI||`books`|Full book catalog — ISBN, title, author, LCCN/call number, shelf number, copy counts, condition, source of fund, and auto-generated QR||`library\\\\\\\_settings`|Single-row configuration table storing capacity, borrow durations, penalty rates, suspension threshold, library hours, and collection target||`attendance\\\\\\\_logs`|Every check-in and check-out event with timestamp and computed visit duration||`borrow\\\\\\\_records`|Every book borrow transaction — borrow date, due date, return date, and status||`penalties`|Per-borrow penalty records for overdue, damage, and lost book cases||`notifications`|In-app notification events categorized by type with read/unread tracking||`announcements`|Library announcements with priority levels and active/inactive toggle||`report\\\\\\\_snapshots`|Cached generated report metadata stored as JSONB for fast reload|### Views|View|Purpose||-|-||`v\\\\\\\_currently\\\\\\\_inside`|Live list of students currently checked into the library (unmatched check-ins)||`v\\\\\\\_active\\\\\\\_borrows`|All active borrow records with overdue flag and days overdue computed||`v\\\\\\\_dashboard\\\\\\\_stats`|Aggregated stats for the dashboard — total books, borrowed, overdue, inside, available slots, and unpaid penalties|### Key Triggers|Trigger|Behavior||-|-||`trg\\\\\\\_book\\\\\\\_qr`|Auto-generates `BK-{isbn}` QR string on book insert||`trg\\\\\\\_user\\\\\\\_qr`|Auto-generates `USR-{student\\\\\\\_id}` QR string on user insert||`trg\\\\\\\_borrow\\\\\\\_decrement`|Decrements `available\\\\\\\_copies` on the book when a borrow record is created||`trg\\\\\\\_return\\\\\\\_restore`|Restores `available\\\\\\\_copies` when a borrow record is marked as RETURNED||`trg\\\\\\\_\\\\\\\*\\\\\\\_updated\\\\\\\_at`|Keeps `updated\\\\\\\_at` accurate on every row update across all major tables|### Scheduled Function`fn\\\\\\\_mark\\\\\\\_overdue\\\\\\\_and\\\\\\\_penalize()` is a PostgreSQL function meant to run daily via a cron job (or Supabase's pg\_cron). It scans all active borrows past their due date, marks them OVERDUE, computes the penalty based on the configured daily rate, updates the user's penalty balance, and automatically suspends users whose unpaid balance exceeds the suspension threshold.### QR Code Format|Entity|Format|Example||-|-|-||Student / Faculty|`USR-{student\\\\\\\_id}`|`USR-2024-MW-0001`||Book|`BK-{isbn}`|`BK-978-0-323-40115-4`|### Penalty Rules (Configurable)|Rule|Default||-|-||Penalty per day (overdue)|₱5.00||Borrow duration — Students|3 days||Borrow duration — Faculty|120 days||Max books per user|2||Suspension threshold|₱100.00||Damage fee|₱5.00||Lost book fee|₱5.00|All of these values are stored in `library\\\\\\\_settings` and editable from the Settings > Library Rules page without touching the database directly.\---## QR Flow```Student Registration└── System generates USR-{student\\\\\\\_id} QR    └── Stored in users.qr\\\\\\\_code        └── Student sees it in mobile appLibrary Entry (Attendance)└── Student opens mobile app → shows QR    └── Librarian desktop webcam scans it        └── 1st scan → CHECK\\\\\\\_IN → attendance\\\\\\\_logs row created        └── 2nd scan → CHECK\\\\\\\_OUT → duration computed, row updatedBook Borrowing└── Librarian scans Book QR (BK-isbn) → identifies book    └── Librarian selects student → creates borrow\\\\\\\_records row        └── available\\\\\\\_copies decremented by triggerBook Return└── Librarian scans Book QR or Student QR    └── System finds active borrow\\\\\\\_record        └── Status set to RETURNED → copies restored by trigger            └── Penalty computed if return is late```\---## Project Structure (Planned)```liblog/├── desktop/                  # Use `UPDATE` not `INSERT` when changing config values from the Settings page.* `available\\\\\\\_copies` on the `books` table is managed entirely by database triggers. Never update it directly from application code.* The attendance toggle logic (first scan = check-in, second scan = check-out) is handled server-side by checking the last `action` value in `attendance\\\\\\\_logs` for that user on the current day.* Notifications are created server-side after each major event (borrow, return, check-in, check-out, penalty). The frontend polls or subscribes via WebSocket.* `report\\\\\\\_snapshots.payload` stores the full aggregated JSON of a generated report so the Reports page can reload the last report instantly without re-querying.\---*LibLog v2.0.0 — Library Logbook Management System © 2026*
